# 系統問題

## 問題討論

[問題1] 算法需要維護對外暴露與呈現數據的功能，所以需要 addAct 函數。以及 Extend 物件。
[目標] 算法可以在運行過程中執行 `addAct(狀態, solution, 對外訊息)` 將狀態提交到緩存中。

[方案] 這個 method 要掛在 `Machine` 物件下面。但是這個問題暫時無法處理，需要對 Machine -> Solver 之間做重構後再處理。預計是要掛在算法執行結果的那個 Result 物件的方法之下，但需要根據目前系統價構重新做評估。

函數名稱為 `addAct(狀態, solution, 對外訊息)` 所以一個算法的數據狀態要切分成內部算法狀態、外部暴露狀態。而函數提交的就是對外暴露的數據狀態。

extend 物件

[問題2] `cli.run` 要可以支援定義直接給 run_seed 陣列然後執行模擬。
[目標] cli.run 要可以重現 cli.exp 的結果，這是必須要的。
[方案] cli.exp 結束後會輸多出一個 seed_bank.json 會對指定的算法組合做結果的重現，算法設定檔那邊可以設定 opt 打開。所以這個問題有三件事要處理。

1. seed 需要在執行 `cli.exp` 後被保存下來。保存至 seed_bank.json 然後把檔案放在 seed folder 中。這個 seed_bamk.json 中保存一個 array。
2. 算法設定那邊需要一個開關。用於判斷是否要用預定的那些 seed 來執行模擬。
3. 模擬的時候需要判斷開關，以及開了之後的後續動作。

[風險] 做這件事有幾個風險，

1. 同一個 run_seed 給不同的算法組合跑結果會不一樣，現在 cli.run 會跑所有的算法組合，這樣的話，當初沒有被處理過的算法組合會跑出不符合預期的結果出來。
2. repeat 次數會有上限如果模擬超過該上限怎搞?
3. 是否能接受若設定檔的算法異動結果就會不同，聽起來很合理。
4. 最大的問題還是在沒有跑過 cli.exp 的算法組合被拿來執行模擬的問題在 cli.exp 實驗過程中不會每一個算法組合都會被拿來跑模擬，可能三組算法中只有一組有跑過 cli.exp 那剩下兩組跑出來的結果就豪無意義。

[新想法] 還是把必需的設定都寫到 seed_bank.json 中然後 看是要在 cli.run 或 cli.exp 做一個重現的功能。或是寫一個獨立的模組用於重現 seed_bank.json 的結果。

然後，不管 seed_bank.json 執行放哪， cli.run 可能需要再多一個參數 `set`。這個參數是用來指定要模擬的參數組合的索引值，從 0 開始。不要讓它們自動執行全部的參數組合。
