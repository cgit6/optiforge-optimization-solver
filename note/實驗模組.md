[方案] 不要判斷要跑哪一組算法參數，跑全部的算法參數組合，比如說模擬算法A、B 他們各有 7、3 組算法參數。那 Simulator 執行模擬的時候會把所有的參數組合都跑過一次。不會去判斷哪一組要跑哪一組不要跑。

`cil.run` 命令參數改名，現在的命令變數名稱都過長了，根據以下改名進行處理:

```
experiment-id -> experiment-name
problem-type -> type
dataset -> dataset
problems -> problems
solver -> solver
param-set-index -> 移除掉
repeat -> repeat
base-seed -> seed
output-dir -> 移除掉
execution-mode -> worker
```

以下幾個是必填，少填就報錯停止模擬
experiment-name
type
dataset
problems
solver

以下幾個選填如果沒填就使用預設參數
repeat -> 預設 20
seed -> 預設 5459385
worker -> 預設 1


然後現在在執行 `cil.run` 時如果 2 組算法，選 1 組參數組合來進行模擬(假設選第3組) 變成說選這兩個算法的 第三組設定進行模擬這件事我覺得也有問題，先不提如果 A 算法有 3 組參數設定 B 算法只有 1 組時的例外情況。


### 算法模組與問題模組的關係

- [] 目前優化問題需要獨立成一個模組，裡面維護各式各樣的優化問題，優化問題的架構 必須有一條或多條目標函數(fitness function) 可能會有限制條件(有的不一定會有) 1 條到數條不等。所以目前算法(bsma_numba)中有 `_fitness_row` 函數是一件很奇怪的事情，算法可以保存目標函數 `_fitness_row = mkp.fitness` 這種方式然後在算法中調用 _fitness_row (因為 numba 不能值接使用物件方法會影響到效能)

- [] 需要在優化問題的物件中定義限制條件的函數。然後視需要在算法中調用。

- `stat 模組`: 處理一下幾件事
  1. [v]修正輸出的 json 格式，多筆資料應該是一個陣列包多個物件而不是多個物件存放在一個檔案中
  2. [v]添加統計值: 當執行完模擬後，計算每一個題目的適應值平均值(Mean)、標準差(Std)、最佳值(Beat，根據問題是 min 還是 max)、最差值(Worst，根據問題是 min 還是 max)、PDev(計算方式是(已知最佳適應值-平均值)/已知最佳適應值\*100%)
- `cil/opt 模組`: 新增該功能模組用於進行組合實驗
  1. [v] 更新算法的 yaml 格式: 改成一份算法設定(e.g. bsma.yaml) 的 params 中可以存放多組的算法設定。然後執行模擬的命令行中添加參數決定要執行哪一組算法設定(cil/run 這邊的執行命令僅支持選擇一組算法參數，判斷參數合法性的流程需要加上這個驗證)

  ```yaml
    - pop_size: 20 # 種群大小

      ctf: abs_pow_17
  ```
