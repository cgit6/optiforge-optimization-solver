# 研究用優化器(mkp) 處理以下幾件事

- `stat 模組`: 處理一下幾件事
  1. [v]修正輸出的 json 格式，多筆資料應該是一個陣列包多個物件而不是多個物件存放在一個檔案中
  2. [v]添加統計值: 當執行完模擬後，計算每一個題目的適應值平均值(Mean)、標準差(Std)、最佳值(Beat，根據問題是 min 還是 max)、最差值(Worst，根據問題是 min 還是 max)、PDev(計算方式是(已知最佳適應值-平均值)/已知最佳適應值\*100%)
- `cil/opt 模組`: 新增該功能模組用於進行組合實驗
  1. [v] 更新算法的 yaml 格式: 改成一份算法設定(e.g. bsma.yaml) 的 params 中可以存放多組的算法設定。然後執行模擬的命令行中添加參數決定要執行哪一組算法設定(cil/run 這邊的執行命令僅支持選擇一組算法參數，判斷參數合法性的流程需要加上這個驗證)

  ```yaml
  params:
    # 第 0 組參數
    - pop_size: 20 # 種群大小
      z: 0.08 # 轉換機率
      ctf: tanh_abs

    # 第 1 組參數
    - pop_size: 20 # 種群大小
      z: 0.03 # 轉換機率
      ctf: sigmoid_s0

    # 第 2 組參數
    - pop_size: 20 # 種群大小
      z: 0.15 # 轉換機率
      ctf: abs_pow_17
  ```

  1. [] 新創建 `cil/exp` 模組，進行多組參數實驗。以下內容相比於 `cil/run` 而有所不同，開發該模組功能時儘量不要動到原本的系統，如果需要動先問我。
     1. 添加實驗 yaml 設定檔 `cil/exp/exp_cfg.yaml`
     2. 執行先讀實驗設定檔 `cil/exp/exp_cfg.yaml` 然後對設定內容做合法性檢查
     3. `executeSimulator` 需要重新設計
     4.
  2. []同時開多組 simulator 進行實驗，目前一個 simulator 僅執行 一個 solver 單一組 config 設定 和一個題庫，目前的實驗需要同時對多算法(bsma、bsca、bscasma)多參數組合(S、U、V 以及算法參數組合，若一個算法三組參數那就是 3x3 需要同時開 9 個 simulator 物件出來跑模擬) 同時執行模擬。這裡就要考慮 SHR 的層級是否能夠共用(不行就算了)，如果 memory 爆了會影響模擬的執行。
  3. []執行組合實驗，根據設定檔中的算法參數(包含轉換函數) 依序跑指定範圍的題目(庫) 然後根據 "自定義判定標準" 判斷是否符合預期若當前題庫的結果符合預期就跑下一個題庫直到所有題庫跑完，如果模擬過程中不符合預期就更新 seed 重新執行，直到全部的題庫結果皆符合 "自定義判定標準" 為止，或是超過 seed 邊界為止(比如說設定 seed 設定從 100~10000，超過 10000 就顯示 "找不到結果" 並停止實驗)。
  4. []可註冊 "自定義判定標準" 寫一個判定邏輯檢查是否通過標準如果通過則保存資料執行下一個題庫。用 register 進行註冊到系統中
  5. []`collect`: 可自定義 "預期符合標準的 seed 數量" 預設是 1。比如說可以設定收 3 個符合條件的數量那模組就會跑到值到收集完 3 個符合條件的 seed 為止。
  6. []輸出並保存檔案，這邊可能要想一下，如果 collect 多組符合預期的結果那資料會不會產生覆蓋?
