目前這個架構下，算法開發人員新增一個 solver 後，通常要做這幾件事。

1. 寫 solver class

放在 `solver/` 底下，例如：

```text
solver/MySolver.py
```

solver class 要符合既有介面，也就是能被 registry 建立，並有：

```python
solve(problem, config, rng) -> SolveResult
```

回傳的 `SolveResult` 要包含解、objective、runtime、run_seed、metadata 等既有欄位。

2. 註冊 solver builder

到 [engine/builders.py](/home/sean/optiforge-optimization-solver/engine/builders.py:15) 加 import 和 builder：

```python
from ..solver.MySolver import MySolver

def solverBuilders() -> dict[str, SolverBuilder]:
    return {
        ...
        "my_solver": lambda: MySolver(),
    }
```

這一步很重要，因為 `Engine` 和 multiprocessing worker 都是靠 `solverBuilders()` 知道有哪些 solver 可以建立。

3. 新增 solver YAML

在 `configs/solvers/` 新增：

```text
configs/solvers/my_solver.yaml
```

內容要包含：

```yaml
solver_id: my_solver
solver_class: MySolver
capabilities:
  problem_types: [mkp]
  encodings: [binary]
  directions: [max]
stop_condition:
  type: max_iterations
  max_iterations: 5000
params:
  - pop_size: 20
    ...
```

重點是：

```text
solver_id 要和 engine/builders.py 註冊的 key 一致。
capabilities 要和題目 type/encoding/direction 相容。
params 會展開成 param_0, param_1, ...
```

4. 在 exp/run 設定中使用它

例如 `cli/exp/exp_cfg.yaml`：

```yaml
solvers:
  - solver: my_solver
    param_idx: [0]
```

或 `cli.run`：

```bash
.venv/bin/python -m mkp.cli.run \
  --experiment-name test_my_solver \
  --type mkp \
  --dataset WEISH \
  --problems weish01 \
  --solver my_solver
```

5. 加測試

至少建議加：

```text
tests/test_my_solver.py
```

測：

```text
可以建立 solver
短迭代可跑完
回傳 feasible result
同 seed 可重現
invalid params 會報錯
```

如果是 Numba solver，還要測第一次 compile 後的第二次可穩定跑。

6. 如果要進 exp evaluator，不一定要改 evaluator

如果只是新算法參與實驗，通常只要加入 `exp_cfg.yaml` 的 solvers 即可。

但如果 evaluator 有寫死 solver id，例如：

```python
brlsmasca_rl_numba
bsma_numba
bsca_numba
```

那新算法若要被 evaluator 判斷，就要改對應 evaluator，例如：

```text
mkp_base
mkp_base2
mkp_calibration
```

否則它只會被當成普通 competitor，或完全不被該 evaluator 看見。

所以最短流程是：

```text
solver class
-> engine/builders.py 註冊
-> configs/solvers/*.yaml
-> exp/run 設定使用
-> tests
```

目前最容易漏的是 `engine/builders.py`，因為 YAML 裡寫了新 solver 但 builder 沒註冊時，實際跑 multiprocessing 會找不到 solver。
