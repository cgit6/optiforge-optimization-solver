# RL_RC_TRAD_ORDER 修改規格

## 1. 修改目標

目前 solver 的主要流程是：

```text
每個 instance 先產生一條 cp_list
所有個體初始化、repair、swap、restart 都使用同一條 cp_list
Q-learning 只負責選擇更新動作：
    action 0 = SMA global
    action 1 = SMA local
    action 2 = SCA sin
    action 3 = SCA cos
```

這次要改成：

```text
仍保留原本 Q-learning 選擇更新動作
但額外增加第二個 Q-learning table
讓每個 individual 在每次 row update 時，動態選擇使用哪一條物品排序

order action 0 = RC_ONLY order
order action 1 = TRAD_ONLY_BEST01 order
```

新版本名稱建議：

```text
RL_RC_TRAD_ORDER
```

核心思想：

```text
RC_ONLY 和 TRAD_ONLY_BEST01 會抓到不同的高品質物品。
固定使用任一條排序都不一定穩定。
讓 population 中不同 individual 在不同搜尋狀態下切換兩條排序，可以利用兩者互補性。
```

這不是把兩條排序線性平均，而是讓 Q-learning 決定：

```text
目前這個 individual、目前這個 state，要用 RC order 還是 TRAD order 來 repair / add / drop / restart。
```

---

## 2. 與目前算法的差異

### 2.1 目前版本

目前版本大致是：

```text
payload = LP relaxation payload
cp_list = LP/RC ordered list

for each row:
    Q-learning 選 update action
    用 update action 產生 binary solution
    用同一條 cp_list 做 repair / add / swap
```

### 2.2 新版本

新版本要變成：

```text
payload = LP relaxation payload

cp_current = 目前 LP/RC order
cp_rc      = RC_ONLY order
cp_trad    = TRAD_ONLY_BEST01 order

for each row:
    state = distance_to_gbest_bin × population_density_bin

    update_action = 原本 Q-learning 選 SMA/SCA 動作
    order_action  = 新增 Q-learning 選 item order

    if order_action == 0:
        selected_order = cp_rc
    else:
        selected_order = cp_trad

    用 update_action 產生 binary solution
    用 selected_order 做 repair / add / swap
```

注意：

```text
不要把 RC / TRAD order 選擇塞進原本 4 個 update action 裡。
要新增第二個獨立的 q_order table。
```

也就是保留：

```text
q_table:   [pop_size, 9, 4]  # 原本更新動作 Q-table
q_order:   [pop_size, 9, 2]  # 新增物品排序 Q-table
```

## 3. 新增參數

在 YAML 的 `params` 裡新增：

```yaml
order_switch_enabled: true
order_switch_policy: rl_rc_trad
order_switch_use_current_in_rl: false
order_switch_alpha: null
order_switch_gamma: null
```

建議規則：

```text
order_switch_alpha = None 時，沿用 alpha
order_switch_gamma = None 時，沿用 gamma
order_switch_use_current_in_rl = false
```

第一版不要讓 RL 在 `current / RC / TRAD` 三者中選，先只讓它在 `RC / TRAD` 兩者間選。原因是前面測試中 `RC_ONLY + TRAD_ONLY` 的互補性最明確，而加入太多 order 會使 Q-learning action space 變大，500 iterations 內學習更不穩。

## 4. 需要新增的兩條物品排序

### 4.1 RC_ONLY order

RC_ONLY 的定義要和本次實驗一致：

```text
RC_ONLY = robust_minmax(reduced_cost) 由大到小排序
```

不要使用你程式裡如果已有的 `score_rc_rank = 0.5 * rc + 0.5 * x_lp` 版本。
本次 `RL_RC_TRAD_ORDER` 實驗使用的是純 reduced-cost order。

實作：

```python
def build_rc_only_order(base_payload: dict[str, Any]) -> tuple[np.ndarray, np.ndarray]:
    reduced_cost = np.asarray(base_payload["reduced_cost"], dtype=np.float64).ravel()
    rc_score = _robust_minmax(reduced_cost)

    item_ids = np.arange(rc_score.size, dtype=np.int64)
    rc_order = np.lexsort((item_ids, -rc_score)).astype(np.int64)

    return np.ascontiguousarray(rc_order), rc_score
```

排序規則：

```text
score 高的排前面
score 相同時 item id 小的排前面
```

---

### 4.2 TRAD_ONLY_BEST01 order

TRAD_ONLY_BEST01 是傳統 CP 類特徵的最佳低成本組合之一。

先定義 normalized weights：

```python
normw = weights / (capacities[None, :] + 1e-12)
```

其中：

```text
weights shape = [items, dim]
capacities shape = [dim]
normw[j, d] = item j 在 constraint d 上消耗 capacity 的比例
```

計算基礎特徵：

```python
sw = normw.sum(axis=1)       # item 的總相對資源消耗
mw = normw.max(axis=1)       # item 在最吃緊單一維度的相對消耗
```

計算 dual pressure：

```python
dual = base_payload["dual_price"]

if dual.sum() > 1e-12:
    pressure = normw @ (dual / (dual.sum() + 1e-12))
else:
    pressure = sw / dim
```

接著計算六個 normalized feature：

```python
value_score      = robust_minmax(values)
sum_weight_eff   = robust_minmax(values / (sw + 1e-12))
max_weight_eff   = robust_minmax(values / (mw + 1e-12))
light            = 1.0 - robust_minmax(sw)
max_light        = 1.0 - robust_minmax(mw)
low_pressure     = 1.0 - robust_minmax(pressure)
```

TRAD_ONLY_BEST01 的權重固定為：

```python
TRAD_W = {
    "light": 0.006743546653452455,
    "low_pressure": 0.43597043345859415,
    "max_light": 0.013316182861006512,
    "max_weight_eff": 0.025911361416350264,
    "sum_weight_eff": 0.17836957605680379,
    "value": 0.33968889955379283,
}
```

計算 score：

```python
trad_score = (
    0.006743546653452455 * light
    + 0.43597043345859415 * low_pressure
    + 0.013316182861006512 * max_light
    + 0.025911361416350264 * max_weight_eff
    + 0.17836957605680379 * sum_weight_eff
    + 0.33968889955379283 * value_score
)

trad_score = np.clip(trad_score, 0.0, 1.0)
```

排序：

```python
item_ids = np.arange(n, dtype=np.int64)
trad_order = np.lexsort((item_ids, -trad_score)).astype(np.int64)
```

完整函數：

```python
TRAD_W = {
    "light": 0.006743546653452455,
    "low_pressure": 0.43597043345859415,
    "max_light": 0.013316182861006512,
    "max_weight_eff": 0.025911361416350264,
    "sum_weight_eff": 0.17836957605680379,
    "value": 0.33968889955379283,
}

def build_trad_only_best01_order(
    values: np.ndarray,
    weights: np.ndarray,
    capacities: np.ndarray,
    base_payload: dict[str, Any],
) -> tuple[np.ndarray, np.ndarray]:
    values_f = np.asarray(values, dtype=np.float64).ravel()
    weights_f = np.asarray(weights, dtype=np.float64)
    caps_f = np.asarray(capacities, dtype=np.float64).ravel()

    n = values_f.size
    dim = caps_f.size
    item_ids = np.arange(n, dtype=np.int64)

    normw = weights_f / (caps_f[None, :] + 1.0e-12)
    sw = normw.sum(axis=1)
    mw = normw.max(axis=1)

    dual = np.asarray(base_payload["dual_price"], dtype=np.float64).ravel()
    if dual.sum() > 1.0e-12:
        pressure = normw @ (dual / (dual.sum() + 1.0e-12))
    else:
        pressure = sw / max(float(dim), 1.0)

    value_score = _robust_minmax(values_f)
    sum_weight_eff = _robust_minmax(values_f / (sw + 1.0e-12))
    max_weight_eff = _robust_minmax(values_f / (mw + 1.0e-12))
    light = 1.0 - _robust_minmax(sw)
    max_light = 1.0 - _robust_minmax(mw)
    low_pressure = 1.0 - _robust_minmax(pressure)

    trad_score = (
        TRAD_W["light"] * light
        + TRAD_W["low_pressure"] * low_pressure
        + TRAD_W["max_light"] * max_light
        + TRAD_W["max_weight_eff"] * max_weight_eff
        + TRAD_W["sum_weight_eff"] * sum_weight_eff
        + TRAD_W["value"] * value_score
    )
    trad_score = np.clip(trad_score, 0.0, 1.0)

    trad_order = np.lexsort((item_ids, -trad_score)).astype(np.int64)
    return np.ascontiguousarray(trad_order), trad_score
```

## 5. 建立 order pool

在 item evaluation / `pseudo_utility()` 階段，除了原本 `self.cp_list`，還要建立：

```text
order_pool[0] = current LP/RC order
order_pool[1] = RC_ONLY order
order_pool[2] = TRAD_ONLY_BEST01 order
```

建議在 `BRLSMASCARLRCNumbaCore.pseudo_utility()` 或類似位置做：

```python
base_order = np.asarray(payload["base_order"], dtype=np.int64)
rc_order, rc_score = build_rc_only_order(payload)
trad_order, trad_score = build_trad_only_best01_order(
    self.values,
    self.weights,
    self.capacities,
    payload,
)

self.order_pool = np.ascontiguousarray(
    np.vstack([base_order, rc_order, trad_order]).astype(np.int64)
)

self.item_eval_payload["rc_order_score"] = rc_score
self.item_eval_payload["trad_order_score"] = trad_score
self.item_eval_payload["order_pool_names"] = [
    "current_lp_rc",
    "rc_only",
    "trad_only_best01",
]
```

如果你想維持向後相容：

```python
self.cp_list = base_order
```

但在 main loop 中，如果 `order_switch_enabled=True`，不要只用 `self.cp_list`，而要用 `self.order_pool[order_id]`。

## 6. 新增 Q-learning order selector

### 6.1 新增 q_order

在 `run()` 裡建立：

```python
q_order = np.zeros((pop_size, 9, 2), dtype=np.float64)
order_action_counts = np.zeros(2, dtype=np.int64)
```

這裡的 `9` 來自你原本 state：

```text
distance_to_gbest_bin = 0, 1, 2
population_density_bin = 0, 1, 2
state = distance_bin * 3 + density_bin
共 9 個 state
```

### 6.2 選 order action

新增 Numba function：

```python
@njit(cache=True)
def _select_q_order_action(q_order: np.ndarray, individual_id: int, state: int) -> int:
    best_value = q_order[individual_id, state, 0]
    if q_order[individual_id, state, 1] > best_value:
        best_value = q_order[individual_id, state, 1]

    tie_count = 0
    for action in range(2):
        if q_order[individual_id, state, action] == best_value:
            tie_count += 1

    pick = np.random.randint(0, tie_count)
    seen = 0
    for action in range(2):
        if q_order[individual_id, state, action] == best_value:
            if seen == pick:
                return action
            seen += 1

    return 0
```

這和你原本 `_select_q_action_non_global()` 的邏輯一致：
初始 Q 值相同時，隨機 tie-break，因此一開始 RC / TRAD 會自然探索。

### 6.3 更新 q_order

新增：

```python
@njit(cache=True)
def _update_q_order_value(
    q_order: np.ndarray,
    individual_id: int,
    state: int,
    action: int,
    reward: float,
    next_state: int,
    alpha: float,
    gamma: float,
) -> None:
    next_max = q_order[individual_id, next_state, 0]
    if q_order[individual_id, next_state, 1] > next_max:
        next_max = q_order[individual_id, next_state, 1]

    current = q_order[individual_id, state, action]
    q_order[individual_id, state, action] = (
        current + alpha * (reward + gamma * next_max - current)
    )
```

reward 沿用目前 update Q-learning：

```text
reward = +1 if this row improves individual_best
reward = -1 otherwise
```

不要另外設計複雜 reward。第一版要和目前實驗一致。

## 7. main loop 修改方式

假設目前 `_bscasma_rl_main_loop_numba()` 接收的是：

```python
cp_list: np.ndarray
```

要改成接收：

```python
order_pool: np.ndarray  # shape = [3, items]
order_switch_enabled: bool
q_order: np.ndarray
order_action_counts: np.ndarray
```

### 7.1 選擇 selected_order

在每個 row 更新前，原本大概是：

```python
state = _state_for_row(...)
action = select update action
```

改成：

```python
state = _state_for_row(...)

# 1. 選 item order
if order_switch_enabled:
    order_action = _select_q_order_action(q_order, individual_id, state)
    # order_action 0 -> RC_ONLY
    # order_action 1 -> TRAD_ONLY
    order_id = 1 + order_action
    order_action_counts[order_action] += 1
else:
    order_action = -1
    order_id = 0

selected_order = order_pool[order_id]

# 2. 選原本 update action
if np.random.random() < z:
    action = 0
else:
    action = _select_q_action_non_global(q_table, individual_id, state)
```

注意：

```text
order_id = 1 + order_action
```

因為：

```text
order_pool[0] = current LP/RC
order_pool[1] = RC_ONLY
order_pool[2] = TRAD_ONLY_BEST01
```

## 8. 哪些地方要改用 selected_order

### 8.1 SMA global row

原本：

```python
_sma_global_row(..., cp_list, ...)
```

改成：

```python
_sma_global_row(..., selected_order, ...)
```

因為 `_sma_global_row()` 是根據 order 逐一嘗試加入 item。

### 8.2 Repair v2

原本：

```python
_repair_bscasma_row_v2_inplace(..., cp_list, ...)
```

改成：

```python
_repair_bscasma_row_v2_inplace(..., selected_order, ...)
```

這是最重要的修改。
RC / TRAD 互補性主要是透過 repair drop/add/swap 轉成解品質改善。

### 8.3 Local search

如果 `local_search_enabled=True`：

```python
_local_search_bscasma_row_inplace(..., selected_order, ...)
```

不過第一輪建議 `local_search_enabled=false`，先確認 order switch 本身效果。

### 8.4 Restart

restart 時也要選 order。建議對每個被 restart 的 row：

```python
if order_switch_enabled:
    state = _state_for_row(...)
    order_action = _select_q_order_action(q_order, individual_id, state)
    order_id = 1 + order_action
else:
    order_id = 0

selected_order = order_pool[order_id]
_restart_bscasma_bucket_biased_row_inplace(..., selected_order, bucket, ...)
_repair_bscasma_row_v2_inplace(..., selected_order, ...)
```

這裡仍然可以沿用原本 `bucket` 來決定 restart 加入機率：

```text
strong_p = 0.85
core_p = 0.50
weak_p = 0.15
```

但 item 掃描順序改成 selected_order。

---

## 9. 哪些地方不需要改

### 9.1 SMA local row

`_sma_local_row()` 本身是逐 item 更新 continuous value，再轉 binary。它不吃 `cp_list`。不需要改。

但它產生 binary solution 後，repair 要用 `selected_order`。

### 9.2 SCA sin / cos row

`_sca_sin_row()`、`_sca_cos_row()` 也不直接吃 `cp_list`。不需要改。

但它們產生 binary solution 後，repair 要用 `selected_order`。

### 9.3 原本 update q_table

原本 `q_table` 照常更新，不要刪。
新增加的 `q_order` 是平行學習，不取代原本 update action learning。

## 10. 初始化怎麼改

目前 mixed initialization 應該會用單一 `cp_list` 做：

```text
10% deterministic greedy
20% LP rounding
40% RCL randomized greedy
剩下 random greedy
```

新版本建議：

```text
BASE mode:
    全部用 current LP/RC order

FIXED_RC_ONLY:
    全部用 RC order

FIXED_TRAD_ONLY:
    全部用 TRAD order

RL_RC_TRAD_ORDER:
    初始 population 在 RC / TRAD 間平均分配
    row i 使用：
        order_id = 1 + (i % 2)
```

也就是：

```python
if order_switch_enabled:
    order_id = 1 + (row % 2)  # 1=RC, 2=TRAD
else:
    order_id = 0

selected_order = order_pool[order_id]
```

這樣初始化時 population 就同時有 RC 型解和 TRAD 型解，能保留兩種排序的互補性。

不要在 RL_RC_TRAD_ORDER 的初始化中使用 current order，否則和前面實驗設定不一致。

## 15. 測試項目

### 15.1 Unit test：order pool 正確性

對任一 OR5x100 instance：

```python
payload = _build_lp_rc_item_eval_payload(...)
current_order, rc_order, trad_order = build_order_pool(...)
```

檢查：

```python
assert order_pool.shape == (3, items)

for oid in range(3):
    assert sorted(order_pool[oid].tolist()) == list(range(items))
```

檢查 RC order：

```python
rc_order, rc_score = build_rc_only_order(payload)

for pos in range(items - 1):
    a = rc_order[pos]
    b = rc_order[pos + 1]
    assert rc_score[a] >= rc_score[b] - 1e-12
```

檢查 TRAD order：

```python
trad_order, trad_score = build_trad_only_best01_order(...)

for pos in range(items - 1):
    a = trad_order[pos]
    b = trad_order[pos + 1]
    assert trad_score[a] >= trad_score[b] - 1e-12
```

預期結果：

```text
三條 order 都是完整 permutation
RC order 按 rc_score 非遞增排列
TRAD order 按 trad_score 非遞增排列
```

## 18. Wilcoxon 檢定

from scipy.stats import wilcoxon

rl = df[df.config == "RL_RC_TRAD_ORDER"].set_index(["problem_id", "seed"])["pdev"]

## 20. 實作時最常見錯誤

### 錯誤 1：把 RC_ONLY 實作成 `0.5 * rc + 0.5 * x_lp`

這會和本次 RL_RC_TRAD_ORDER 實驗不一致。
這次 RC_ONLY 要用：

```text
robust_minmax(reduced_cost)
```

### 錯誤 2：把 RC 和 TRAD 線性平均成一條排序

這不是 RL_RC_TRAD_ORDER。
本方法是：

```text
每個 individual 每次動態選 RC 或 TRAD
```

不是：

```text
score = 0.5 * RC + 0.5 * TRAD
```

### 錯誤 3：只在 initialization 用不同 order，repair 還是用原本 cp_list

這樣效果會大幅縮小。
最重要的是 repair/drop/add/swap 要用 selected_order。

### 錯誤 4：只更新 update q_table，沒有更新 q_order

要同時更新：

```text
q_table  # 選更新動作
q_order  # 選物品排序
```

### 錯誤 5：排序後 individual_id 搞丟

你目前 q_table 是根據 `individual_id` 存，不是根據 row 存。
排序 population 後，`individual_ids` 必須一起排序。
`q_order` 也應該用同一個 `individual_id` 查表，不要用 row index。

## 21. 最小修改版總結

最小可行修改是：

```text
1. 建立 rc_order
2. 建立 trad_order
3. 建立 order_pool = [current_order, rc_order, trad_order]
4. 新增 q_order = zeros([pop_size, 9, 2])
5. 每個 row 更新時：
      state = current state
      order_action = select q_order action
      selected_order = order_pool[1 + order_action]
6. selected_order 傳給：
      SMA global
      repair v2
      local search
      restart
7. 用原本 reward 同時更新 q_table 和 q_order
8. metadata 記錄 order count / ratio / q_order_nonzero
```
